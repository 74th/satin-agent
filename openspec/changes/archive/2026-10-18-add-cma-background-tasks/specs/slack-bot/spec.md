# Spec Delta

## MODIFIED Requirements

### Requirement: 実行中の追加指示
Botは、turnの実行中に同じスレッドへ書き込まれた指示を、そのセッションへ送らなければならない (SHALL)。モデルが応答を生成している間はそのまま送らなければならない (SHALL)（現在のturnの後に続けて処理される）。バックグラウンド実行のツール（`run`・`task_status`・`task_wait`・`task_stop`。最長60秒で返る）の実行中は、ツールを中断せずに、その結果が返った後に送らなければならない (SHALL)。それ以外のツールの実行中または確認待ちの間は、`user.interrupt`で実行中のツールを中断してから送らなければならない (SHALL)（Managed Agentsはツール実行中のメッセージ送信を受け付けず、ツールを止めずに指示を届ける方法がないため）。進捗メッセージには追加した指示の件数を表示しなければならない (SHALL)。1つのスレッドで、2つのturnを並行して実行させてはならない (SHALL NOT)。

#### Scenario: ツール実行中の割り込み
- **WHEN** エージェントが組み込みのbashで`sleep 30`を実行している間に「終わったらdateも実行して」と書き込む
- **THEN** 実行中のツールは中断され、追加の指示がセッションへ送られ、エージェントは`date`を実行して報告する。進捗メッセージには追加の指示が1件と表示される

#### Scenario: バックグラウンド実行のツールの実行中
- **WHEN** エージェントが`run`で`sleep 300`を実行している間（バックグラウンドへ回る前）に「ついでにdateも実行して」と書き込む
- **THEN** `run`は中断されずにタスクIDを返し、その後に追加の指示がセッションへ送られ、エージェントは`date`を実行して報告する。`sleep 300`のタスクは動き続ける

#### Scenario: 応答の生成中の追加
- **WHEN** エージェントがツールを使わずに応答を生成している間に追加の指示を書き込む
- **THEN** 指示はそのままセッションへ送られ、現在のturnの後に続けて処理される

## ADDED Requirements

### Requirement: バックグラウンドのタスクの表示と終了の通知
Botは、`run`がバックグラウンドへ回したタスクを、進捗メッセージに、ツールとは区別して「バックグラウンドで実行中」と表示しなければならない (SHALL)。turnが終わったときにバックグラウンドのタスクが残っていれば、完了の表示にその件数を含めなければならない (SHALL)。Botは、状態のConfigMapで、セッションのエージェントに伝えていないまま終わったタスクを見つけたら、そのタスクの終了をエージェントに知らせる`user.message`をセッションへ送り、新しいturnとして進捗と返答を表示しなければならない (SHALL)。turnの実行中に見つけた場合は、追加の指示と同じ扱いで送らなければならない (SHALL)。同じタスクの終了を2回以上知らせてはならない (SHALL NOT)。この知らせはBotが作る文なので入力ガードには通さないが、監査フックには渡さなければならない (SHALL)。

#### Scenario: turnの後にタスクが終わる
- **WHEN** エージェントが`sleep 60; echo done`をバックグラウンドへ回して「終わったら報告します」と返答し、turnが終わる
- **THEN** 進捗メッセージは完了（バックグラウンド1件）になり、約60秒後に同じスレッドに新しい進捗メッセージと、タスクの結果を報告する返答が投稿される

#### Scenario: Botの再起動をまたぐ
- **WHEN** バックグラウンドのタスクが動いている間にBotのPodを削除し、Botが再起動した後にタスクが終わる
- **THEN** 再起動したBotが終了を1回だけセッションへ知らせ、エージェントの報告がスレッドに投稿される
